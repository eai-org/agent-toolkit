# SELF-REVIEW-TEST — measuring harness for self-review

Runs [self-review](../../skills/self-review/SKILL.md) headlessly over fixture repos with planted
defects and scores what it caught, what it invented and what it cost, so a change to the skill
(or to the [fresh-eyes-review](../../skills/fresh-eyes-review/SKILL.md) it drives) is judged on
numbers, not impressions. Repo-internal: `test/` is never installed.

## What it measures

- **Recall** — planted defects found, overall and for blocking ones (`defects.tsv`).
- **Precision** — findings matched to a defect over all findings the skill did not refute itself;
  every unmatched finding is a false-positive candidate the owner reads (`score.md`), never a
  verdict by itself. Unlabelled real problems count as unmatched — add them to the labels when
  the reviewer is right.
- **Traps** — correct code that looks wrong (`traps.tsv`); a flagged trap is a false positive.
- **Merged** — findings credited with two or more defects: distinct mistakes on one line.
- **Cost** — tokens over every model the run used (main session and subagents, from the result
  JSON's `modelUsage`), tokens per changed line, USD, turns, subagents spawned, minutes. Per-agent
  splits come from the session transcripts the agent CLI saves.
- **Report shape** — the structure the skill mandates: visible part, `<details>` with the blank
  line after `</summary>`, hashes, rounds.

The run exercises the skill end to end under `autoaccept`: target detection, intent from the
planning home, the fresh-eyes reviewer, dispositions, fixes applied to the working tree
(`fixes.diff`), later rounds, the report.

## Fixtures

`fixtures/<case>/`: `base/` (the tree committed on `main`), `change/` (the overlay committed on
`feature/<case>`; `change/.deleted` lists removed paths), `intent.txt` (one paragraph; becomes the
fixture's `REQUIREMENTS.md`, the intent source the skill prefers), `defects.tsv` and `traps.tsv`.

- `small-defects` — a Python orders service gaining coupons and a cancellation window: 10 defects
  across the kinds a reviewer must catch (intent mismatch, convention, None handling, inverted
  condition, swallowed exception, leftover, tautological test, omitted counterpart, missing test,
  docs), 2 traps, ~120 changed lines.
- `small-clean` — the same service gaining order notes, done right: 0 defects, 2 traps. Any
  finding is a false positive.
- `small-uncommitted` — `small-defects` with only its new files committed, its edits to existing
  files left in the working tree: an unpinned review whose fixes land in uncommitted files.
  `.git/fixture-start` records the state under review (a `git stash create` commit), which the
  scorer diffs against.
- `big-pr` — generated by [gen-big-pr.py](gen-big-pr.py) at run time (`MODULES` entities,
  default 40): soft-archive across every entity, ~3,000 reviewable lines plus mechanical files (a
  4,000-line lockfile, a minified bundle, snapshots), 11 defects (one is the lockfile itself,
  changed with no manifest), 3 traps.
- `incident` — generated by [gen-incident.py](gen-incident.py): a TypeScript monorepo whose
  branch switches the inspection screens between a legacy and a v2 API behind a server flag. It
  carries the drivers of the runaway review this harness was built after: diffs above the agent
  CLI's output limit, a regenerated 64-file API client with one model hand-edited, backend
  contracts outside the diff the frontend relies on, change docs shipped with the PR, governing
  docs and project skills. 18 defects (contracts, flag-off regression, vocabulary, null handling,
  swapped fields, generated drift, data loss, double rotation, unprovided root URL, leak, intent,
  omissions, test gaps, conventions), 2 traps, ~3,650 added lines. On Sonnet the reviewer reads
  frugally and never runs away as the frontier model did in the original incident; there the fix
  work dominates the cost.

Labels: `defects.tsv` is `id, sites, kind, blocking, description`; `traps.tsv` is
`id, sites, description`. `sites` is `path:line`, `path:lo-hi` or `path:*` (anywhere in the
file), several joined by `|`. Lines are of the feature tree; a defect's site must touch an added
line unless its kind is `omission` or `missing_test` (those point at the place the change should
have touched). `selfcheck` validates this.

Matching: a finding cites `path:line` sites inside backtick spans; a shortened path
(`photo.mapper.ts`, `libs/.../x.ts`, `ui/photo-gallery/x.ts`) matches when its file name does and
its other segments appear in the label's path in order. A cited line hits a label site within
`--tolerance` lines (default 5), a `path:~N` estimate within 15. Off by up to 15 (reviewers cite
up to a dozen lines off), a line hits only when the finding's text backs the defect's
description, file name aside — two shared word stems, or quoted code found in it (`console.log`,
`assignee!`, not a plain short word like `ngOnInit`) — and ranks behind exact hits. A file-only
citation hits on one shared stem, after every line hit. Each defect goes to its closest hitting
finding, round-1 findings first (later rounds review fixes); a defect no finding claimed alone
goes to a finding that already claimed another, since a line naming two failures tells the reader
both — never through an off-line citation; that finding counts as merged. Estimates and
file-only citations never count as trap hits.

Never tune a fixture toward the current skill text: a new kind of miss gets a new defect, a
false positive the owner judged wrong gets a trap.

## Procedure

Recommended runs, cheapest first. Sonnet keeps every case under 2 USD, though its recall is not
the frontier model's; the caps stop a runaway early.

```sh
bash test/self-review/run.sh selfcheck                                  # free
MODEL=sonnet BUDGET_SMALL=3 bash test/self-review/run.sh small-defects small-clean
MODEL=sonnet BUDGET_BIG=3 bash test/self-review/run.sh big-pr
MODEL=sonnet BUDGET_INCIDENT=5 bash test/self-review/run.sh incident
```

Per LLM case the runner builds the repo with [make-fixture.sh](make-fixture.sh) in a fresh temp
dir (outside this repo, so its `AGENTS.md` never loads), links the checkout's `skills/` into
`.claude/skills/`, runs `claude -p --setting-sources project --dangerously-skip-permissions
--max-budget-usd … "/self-review autoaccept"` (the agent CLI is the harness; another agent needs
the equivalent headless flags), then scores with [score.py](score.py). Autoaccept still asks
before a fix that reshapes the change and before reviewing a diff above the size limit (no
fixture at its default size reaches it); either ends a headless run without a report: the runner
then resumes the session with "go with your recommendation", at most twice, and the scorer counts
the session's cumulative usage once, turns and subagents summed over the resumes. Budgets cap the
damage of a runaway run: `BUDGET_SMALL` (8 USD), `BUDGET_BIG` (30 USD), `BUDGET_INCIDENT`
(10 USD); a run the cap stopped scores with status `error_max_budget_usd` and stays in the table —
the overrun is the result.

Reference cost on Sonnet (self-review 1.1, 2026-10-24): small cases 0.2–1.2M tokens, 0.2–0.7 USD;
big-pr 0.9–1.2M tokens, 0.5–0.8 USD; incident 2.7–3.2M tokens, 1.5–1.8 USD. On Opus
(self-review 1.1 at `e44273c`, 2026-10-26, one run each): small cases 0.3–1.2M tokens, 0.4–1.5
USD; big-pr 1.4M tokens, 1.5 USD; incident 10.2M tokens, 6.5 USD. On Fable (2026-10-27, one
run): incident 4.8M tokens, 13.3 USD.

`selfcheck` costs nothing: it builds every fixture, validates the labels, and scores an oracle
report (must reach recall 1, precision 1) and a null report (0 findings).

**Old vs new.** `SKILLS_REF=<git ref>` runs the skills as exported from that ref (`HEAD` while the
new versions are uncommitted, a tag or `main` later) instead of the working tree. Same model, same
fixture, same budget, then [compare.py](compare.py) puts the two sides next to each other —
tokens, cost, recall, merged and unmatched findings, and how often each planted defect was
matched. A side is one run dir or several, comma-separated; over several samples of a case it
prints the median and range:

```sh
MODEL=sonnet SKILLS_REF=HEAD BUDGET_INCIDENT=5 bash test/self-review/run.sh incident   # old
MODEL=sonnet BUDGET_INCIDENT=5 bash test/self-review/run.sh incident                   # new
python3 -I test/self-review/compare.py test/self-review/runs/<old-1>,test/self-review/runs/<old-2> test/self-review/runs/<new> incident
```

Read a run as a whole, not one number: a high recall with ten unmatched findings is noise, a low
cost with a missed blocking defect is a regression. One run is a point estimate — round counts and
fix choices swing tokens up to 2× between identical runs — so repeat before acting on a gap:
`REPEAT=N` runs each LLM case N times, into `<case>.<n>/`. Compare
runs with `BASELINE_DIR`: copy a good run's `score.json` per case there and the next run gates on
recall (−0.10) and tokens (+25%).

## Run log

`runs/<timestamp>-<suffix>/` (gitignored, unique per runner): per case (`<case>.<n>/` with `REPEAT`)
`result.json` (the raw result, plus `result-resume-N.json` per resume), `claude.err`, `report.md`
(the scored `SELF-REVIEW.md`), `fixes.diff`, `score.json`, `score.md` (matched, missed, unmatched
and trapped findings to read); `summary.tsv` across cases. Fixture repos stay in `FIXTURE_ROOT` for
inspection (the runner prints it).

A finding worth a skill change goes through `/self-improve`, never a direct edit; a fixture change
that moves a label regenerates nothing but needs `selfcheck` green.
